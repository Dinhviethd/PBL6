## Đối chiếu code và API

- `client/src/pages/organizer/CreateEventPage.tsx` tạo event rồi chỉ hiển thị link về `/organizer`; `EditorPage.tsx` tại `/organizer/events/:id` đã thêm/sửa/ngừng dùng loại vé và gửi duyệt, nhưng không có bảng/layout B5 hay sidebar riêng. Route `:id/:tab` đã dùng cho Operations, route mới phải tránh xung đột. Không thay code.
- Đọc `server/src/app.ts`, `server/src/workflows/booking.ts`, `server/src/modules/order/infrastructure/store.ts`: `GET /organizer/events/:id` bao gồm mọi `ticketTypes`; POST `/organizer/events/:id/ticket-types`, PATCH/DELETE `.../:typeId`, POST `/organizer/events/:id/submit` có route/protect. Chưa gọi POST/PATCH/DELETE vé trong phiên này, chưa xác minh runtime hoặc tích hợp B5. Quy tắc chi tiết và dữ liệu kiểm thử hợp lệ được ghi trong [kế hoạch](../../ui/Feature_B5_CreateTickets.md).
- Bằng chứng runtime có sẵn từ phiên B4: GET event 200 và submit không có vé 400 `MISSING_TICKETS` trong API source/DB test cô lập; không suy rộng sang CRUD vé hay môi trường Docker 8000. Không xác minh runtime thêm trong phiên tài liệu này.
- API chỉ cho phép cấu hình vé khi event `DRAFT`/`REJECTED`, giá nguyên dương tối đa 15 chữ số, capacity 1–1.000.000, sale start < end <= event end; PATCH toàn bộ, capacity >= sold+reserved; DELETE archive, không cho nếu đã bán/giữ. Submit kiểm tra loại chưa archive, sau thành công là `PENDING_REVIEW`.
- Stitch giả định xuất báo cáo, chuyển đổi/khóa vé riêng, QR 45 giây, anti-scalping/refund, live sync 5 giây, zone/code/đặc quyền, thẻ QR mẫu và nhãn đã gồm phí. Không thấy contract tương ứng trong phạm vi kiểm tra; không khẳng định hỗ trợ. Cần quyết định và phê duyệt các sai lệch khi triển khai; chưa xác nhận quy tắc sắp hết hay trạng thái mở bán.
