## 5. API đã xác minh

Môi trường: Docker local `http://localhost:8000`; client gọi qua `/api` (Vite proxy khi chạy dev). Tất cả yêu cầu dưới đây đã thực hiện thật, không mock.

| API | Kết quả xác minh | Tích hợp |
|---|---|---|
| `GET /api/health` | HTTP 200, `{ success: true, data: { status: "ok" } }` | Xác nhận môi trường sau rebuild |
| `POST /api/auth/login` | Thành công, trả `accessToken` và user; admin đăng nhập được | Dùng để kiểm thử quyền admin |
| `POST /api/me/organizer-applications` | Thành công, trả hồ sơ `PENDING`; đủ 11 trường bắt buộc | Form nộp hồ sơ |
| `GET /api/me/organizer-applications` | Thành công, trả mảng hồ sơ thật, sắp xếp `created_at DESC` | Tab theo dõi trạng thái |
| `POST /api/admin/organizer-applications/:id/review` | Thành công với `approve: true`; hồ sơ chuyển `APPROVED`, tài khoản được cấp `ORGANIZER` | Kiểm thử trạng thái đã duyệt |
| `POST /api/admin/organizer-applications/:id/review` | Thành công với `approve: false` + lý do; hồ sơ chuyển `REJECTED`, lý do được trả lại | Kiểm thử trạng thái từ chối và nộp lại |

Ghi chú hợp đồng:

- Request nộp hồ sơ bắt buộc: `organizationName`, `contactName`, `contactEmail`, `contactPhone`, `description`, `businessName`, `taxIdOrBusinessLicense`, `websiteOrSocial`, `headOfficeAddress`, `mainEventCategory`, `expectedEventScale`.
- Response là snake_case (`organization_name`, `business_name`, `created_at`, ...), được component ánh xạ khi hiển thị.
- Review từ chối bắt buộc `reason` không rỗng; check constraint database cũng chặn trạng thái `REJECTED` thiếu lý do.
- Chỉ cho phép một hồ sơ `PENDING` trên mỗi người dùng; UI chặn gửi thêm và hiển thị cảnh báo.

## 9. Vấn đề đã giải quyết

- **Lỗi `23502` khi nộp hồ sơ:** container API đang chạy image cũ, thiếu cột/khớp schema mới. Đã rebuild image và recreate container; API trả `PENDING` bình thường. Không sửa source backend cho lỗi này.
- **Khôi phục nháp rỗng:** bản nháp không còn giá trị sẽ bị bỏ qua, không hiện thông báo "đã khôi phục" sai.
- **H1 bị ngắt dòng không đẹp:** giữ cụm "Ban tổ chức" trên một dòng; H1 hiển thị ba dòng ở desktop/mobile.
- **Dấu `*` trường bắt buộc quá mờ:** tăng kích thước và giữ màu cyan.
- **Dữ liệu kiểm thử bị méo chữ:** một lần tạo bằng PowerShell bị sai encoding; đã xóa và tạo lại bằng Node/UTF-8. Đây là lỗi công cụ kiểm thử, không phải lỗi ứng dụng.

## 10. Vấn đề còn tồn tại và giới hạn

1. **Không có API nháp backend:** nháp chỉ tồn tại trên trình duyệt hiện tại; xóa dữ liệu trình duyệt sẽ mất nháp.
2. **Chưa có Playwright spec cố định cho A5:** các bài kiểm thử trong phiên là script tạm và đã xóa; chưa thêm test vào `client/tests/`.
3. **Admin UI chưa được kiểm thử:** duyệt/từ chối được gọi trực tiếp qua API review; chưa thao tác trên màn hình Admin C4–C6.
4. **Accessibility chưa audit đầy đủ:** chưa kiểm tra screen reader, thứ tự focus toàn trang và tỷ lệ tương phản bằng công cụ.
5. **Đồng bộ quyền sau duyệt:** trang A5 nhận trạng thái `APPROVED` ngay từ API; thanh điều hướng có thể cần tải lại/đăng nhập lại để hiện mục Organizer. Đã ghi trong thông báo trên trang.
6. **Chưa đo sai khác pixel với Stitch:** chỉ đối chiếu bố cục/token bằng ảnh và HTML.
7. **Ảnh Cloudinary có chữ bị cắt trong khung dọc:** đây là cách trình bày visual đã chọn; không ảnh hưởng chức năng.
