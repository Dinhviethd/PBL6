## Server thực và môi trường test

- Live: `https://eventhubqrmarketing.tech/api`. 37 HTTP requests trong lượt xác minh hoàn chỉnh: **36 HTTP 200**, **1 HTTP 403 đúng quyền Customer → Admin**. Login `/auth/mobile/login`, `/auth/me` và logout của ba tài khoản demo xác nhận USER / USER+ORGANIZER / USER+ADMIN. Các API dữ liệu chỉ GET; không tạo đơn/chuyển tiền/duyệt/khóa dữ liệu Live.
- Health/config/events/categories, history/tickets/notifications/assignments/applications, organizer dashboard/profile/events/detail/order-manager/attendees/analytics/checkins/staff và admin stats/revenue/users/applications/events/payments/transactions/settings/administrators đã trả đúng HTTP trong lượt đó. `config` trả paymentMode disabled, sepayEnabled true; không dùng thanh toán demo thay thế Live.
- Lượt kiểm tra ban đầu đã gọi nhầm hai URL số ít `/me/organizer-application`, `/me/organizer-profile` và nhận 404; sửa script theo route source rồi xác minh lại đúng `/me/organizer-applications`, `/organizer/profile` đều 200. Không thay UI để che lỗi hợp đồng.
- Mutation và UI tự động chỉ trên PostgreSQL/Mailpit/API **local riêng**: API8016, DB55433, SMTP1026/inbox8026, preview8083. Có kiểm thử webhook SePay tổng hợp, không gọi ngân hàng thật.
- Backend giữ nguyên giới hạn auth 20 credential requests/phút. Lượt ghép suite quá nhanh gặp429; thêm pacing fixture15s giữa scenario để giữ chính sách thật, không bỏ rate limit. Một lượt test trước bị gián đoạn khi export ghi lại dist trong lúc suite đang chạy; lượt cuối chạy tuần tự export → tests, không tính lượt đó là PASS.
