- **Mã & tên màn hình:** B3 — Tạo / chỉnh sửa sự kiện (`/organizer/new`, `/organizer/events/:id`), component `client/src/pages/organizer/EditorPage.tsx`.

- **Thời gian / loại hành động:** 2026-10-28 16:06 (UTC+07:00) — `implementation` (thay đổi API + giao diện).

## 1. Yêu cầu liên quan

Theo kế hoạch đã được người dùng phê duyệt:

1. Khi tạo sự kiện: **bỏ hẳn ô nhập slug**; slug được tự sinh từ `title` (ví dụ `Âm Nhạc` → `am-nhac`).
2. Khi sửa sự kiện: hiển thị slug **read-only**.
3. Khi đổi `title` khi sửa: **giữ nguyên slug cũ**.
4. **Không chỉnh sửa database** (không migration/schema). Được phép tạo rồi xóa 1 sự kiện test để kiểm thử.

Liên quan Master Plan: mục 4 dòng 5 (`POST/PATCH /organizer/events/*`) và luồng nghiệp vụ 5 (Organizer tạo sự kiện → gửi duyệt).

## 2. Trạng thái thiết kế ban đầu

- `server/src/app.ts`: `eventSchema` có `slug` bắt buộc (`text.regex(/^[a-z0-9-]+$/).max(220)`).
- `server/src/modules/event/infrastructure/store.ts`: `save` dùng `d.slug` cho cả INSERT và UPDATE; cột `events.slug` là `NOT NULL UNIQUE`.
- `client/src/pages/organizer/EditorPage.tsx`: ô nhập slug tự do "Đường dẫn (chữ thường, dấu gạch ngang)" hiển thị ở cả chế độ tạo và sửa.

## 3. Tiêu chí nghiệm thu

- [x] `POST /organizer/events` không cần `slug`, vẫn tạo thành công với slug sinh tự động.
- [x] Slug sinh từ tiếng Việt có dấu đúng quy tắc (bỏ dấu, thường, gạch nối, cắt 200 ký tự).
- [x] Slug không trùng: tự thêm hậu tố `-2`, `-3`, … (kiểm tra qua `events.bySlug`).
- [x] `PATCH /organizer/events/:id` không gửi `slug` thì giữ slug cũ, kể cả khi đổi `title`.
- [x] Giao diện tạo không còn ô slug; giao diện sửa hiển thị slug read-only (disabled, không gửi lên).
- [x] Không thay đổi schema database.
- [x] Tạo rồi xóa đúng 1 sự kiện test.

## 4. Thao tác đã thực hiện

1. Tạo `server/src/utils/slug.ts` — `slugify(title)` chuyển tiếng Việt có dấu → không dấu, thường, gạch nối; fallback `su-kien-<8 hex>` khi rỗng.
2. `server/src/app.ts` — `eventSchema.slug` thêm `.optional()`.
3. `server/src/modules/event/public.ts` — thêm `uniqueSlug(title)` (lặp `r.bySlug`, hậu tố `-2`, `-3`…); trong `create` gán `d.slug = await uniqueSlug(d.title)` khi thiếu.
4. `server/src/workflows/booking.ts` — trong `saveEvent` nhánh sửa: `d.slug = d.slug || e.slug` trước `events.save` (giữ slug cũ khi không gửi slug).
5. `client/src/pages/organizer/EditorPage.tsx` — bỏ ô slug ở chế độ tạo; ở chế độ sửa hiển thị `<Field label="Đường dẫn (tự động)" disabled required={false} value={e.slug} />` (read-only, không gửi lên).

## 6. Bằng chứng kiểm thử

**Unit (`slugify`)**

| Input | Output |
|---|---|
| `Âm Nhạc` | `am-nhac` |
| `Sự kiện kiểm thử slug tự động` | `su-kien-kiem-thu-slug-tu-dong` |
| `  Đẹp   Trai  !!!  ` | `dep-trai` |
| `!!!` | `su-kien-<8 hex>` (fallback) |
| `AC/DC Live @ Đà Nẵng` | `ac-dc-live-da-nang` |

**Integration (server local `http://127.0.0.1:8001`, tài khoản organizer, database Supabase thật)**

- `POST /organizer/events` **không gửi slug**, title `Sự kiện kiểm thử slug tự động` → HTTP 200, `slug = "su-kien-kiem-thu-slug-tu-dong"`.
- `PATCH /organizer/events/:id` đổi title `Đổi tên để kiểm tra giữ nguyên slug`, **không gửi slug** → HTTP 200, `slug` vẫn `"su-kien-kiem-thu-slug-tu-dong"`.
- Dọn dẹp: xóa trực tiếp 1 dòng `events` qua SQL (không có endpoint xóa cứng; chỉ có `POST /organizer/events/:id/cancel`). `DELETE FROM events WHERE id=...` trả `rowCount = 1`.

**Build/typecheck**

- Server: `npx tsc --noEmit` PASS (không lỗi).
- Client: `npm run build` (`tsc -b` + `vite build`) PASS.
