## API và bằng chứng runtime

| Method / endpoint | Vai trò | Bằng chứng |
|---|---|---|
| `GET /api/health` | Health check backend | Local `localhost:8000`, HTTP 200, `{"success":true,"data":{"status":"ok"}}` |
| `GET /api/config` | Cấu hình thanh toán | Local `localhost:8000`, HTTP 200; `paymentMode=disabled`, `sepayEnabled=true` |
| `GET /api/me/order-history/:id` | Nạp order/payment/ticket summary cho A7 | Gọi không có phiên đăng nhập trả HTTP 401 `UNAUTHORIZED`; xác nhận route yêu cầu auth. Chưa có phiên/order hợp lệ để xác minh response thành công. |

Source backend xác nhận detail kiểm tra `buyer_id` và enrich dữ liệu `payment`, `tickets`, `ticketList`. A7 gọi bằng Axios client hiện có, tự đính kèm auth. Runtime response của order PAID chưa kiểm chứng. Invoice/PDF endpoint không có trong phạm vi đã xác minh; A7 không gọi endpoint đó.

## Kết quả triển khai

- Success chỉ render khi API order-history trả `status === "PAID"`; order code, event title, amount, payment method/time và ticket counts lấy từ API.
- Với trạng thái khác PAID, UI không hiển thị success; cung cấp kiểm tra lại và quay về Checkout. API error hiển thị lỗi/retry.
- CTA trỏ tới `/tickets`, `/orders`, `/explore`. Không tạo QR, hóa đơn PDF, transaction reference hoặc data mẫu.
- Header/footer do App shared shell cung cấp. UI dùng nền tối, surface Cosmic Graffiti, cyan/tím/hồng, Syne/Space Grotesk và breakpoint CSS 700px.
- Stitch artifact giữ nguyên. Selector và các trạng thái pending/failure có trong artifact không được đưa vào page A7 theo yêu cầu success-only đã ghi trong plan.
