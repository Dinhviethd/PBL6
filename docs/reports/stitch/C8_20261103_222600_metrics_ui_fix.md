## Thay đổi

- Metrics query đã dùng SELECT/VALUES thay CTE `WITH`, tránh `assertOwned()` từ chối câu lệnh với `Unsupported runtime SQL for order`.
- `GET /admin/events/metrics` trả thêm `ticketCapacity` bên cạnh `ticketsSold`, `ticketsIssued`, `checkins`, `checkinRate`, `gmv` và `revenue`.
- Cột “Vé · check-in” hiển thị vé đã bán / sức chứa, số phát hành và check-in; thêm hai progress bar có `role=progressbar`, accessible label và giá trị hiện tại.
- Rebuild/recreate API bằng `docker compose up -d --build api`, đồng thời nạp bundle C8 mới vào `/admin/events`.

## Xác minh runtime và giao diện

- Login ADMIN: HTTP 200; `GET /admin/events`: HTTP 200, 5 sự kiện; `GET /admin/events/metrics`: HTTP 200, 5 metrics. Response có `ticketCapacity` và các trường vé/check-in/doanh thu.
- Tổng mẫu 5 sự kiện đầu: capacity 119; sold 9; issued 9; check-ins 3; doanh thu 95.000 VND.
- Smoke Chrome trên container mới, viewport 1440×900: 10 event rows; 20 progress bars; ví dụ hàng đầu “1 / 35 vé, 1 đã phát hành, 1 check-in · 100%”, doanh thu 15.000 VND; không lỗi page script.
- Resize 390×844: document rộng 390px, không tràn ngang toàn trang; bảng rộng 1200px cuộn ngang trong vùng bảng rộng 364px.
- Server/client build PASS; client lint PASS; ownership test 3/3 PASS; module boundary PASS.

Số liệu trên là dữ liệu thật từ API đang chạy, không phải fixture/mocked UI. Tỷ lệ vé dùng `sold_quantity / capacity`; tỷ lệ check-in dùng `checkins / ticketsIssued`, chặn tối đa 100% khi vẽ thanh. Revenue và GMV cùng phản ánh tổng PAID như đã ghi ở report triển khai trước.
