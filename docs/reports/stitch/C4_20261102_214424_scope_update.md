## 2. Nội dung chốt phạm vi

Theo yêu cầu bổ sung của người dùng, phiên triển khai C4 tới sẽ:

1. **Chỉ tập trung giao diện C4**, không đụng màn hình khác (C5, C6 và các màn admin khác giữ nguyên).
2. **Bổ sung API** để thực hiện các chức năng:
   - **3 KPI tổng hợp:** tổng đối tác / đang hoạt động (APPROVED) / chờ thẩm định (PENDING).
   - **Tìm kiếm `q`** (không phân biệt hoa thường trên tên công ty / người đại diện / MST…).
   - **Lọc `status`** (PENDING / APPROVED / REJECTED).
   - **Tổng doanh thu (GMV)** theo từng ban tổ chức.
   - **Phân trang** (`total` / `totalPages`).
3. **Loại bỏ các chức năng còn lại** khỏi UI, không mock, không hard-code.

## 3. API hiện có (đã xác minh ở phiên gốc)

| Endpoint | Method | Bằng chứng |
|---|---|---|
| `GET /admin/organizer-applications` | GET | 401 không token; 200 token admin, `{success,data:[...]}` (3 bản ghi: 2 APPROVED, 1 REJECTED); mảng phẳng, không `total`/`q`/`status` |
| `POST /admin/organizer-applications/:id/review` | POST | Source: `{approve, reason}` (reason bắt buộc khi từ chối) |

## 4. API cần bổ sung (phiên triển khai)

Mở rộng **chỉ** `GET /admin/organizer-applications` (giữ nguyên `/me/organizer-applications` cho A5):

- Tham số mới: `q`, `status`, `page`, `limit`.
- Response envelope:
  ```
  {
    success: true,
    data: {
      stats: { total, active, pending },
      pagination: { total, totalPages, page, limit },
      items: [ { ...fields hiện có, gmv: "..." } ]
    }
  }
  ```
- `gmv` = tổng `orders.total_amount` của đơn `status='PAID'` thuộc các sự kiện có `events.organizer_id = application.user_id` (đã xác minh quan hệ trong repo; trả string để tránh tràn BigInt).
- 3 KPI = đếm toàn bộ `organizer_applications` trong cùng snapshot.
