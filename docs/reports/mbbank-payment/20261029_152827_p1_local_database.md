Ngày: 29/10/2026 (UTC+7). Phạm vi: P1; không triển khai API SePay. Người dùng xác nhận chưa có PostgreSQL local cần giữ và cho phép tạo môi trường riêng theo đề xuất.

Không đưa giá trị vào log/report; không copy dữ liệu Supabase.

## File và thiết kế

- `compose.sepay-local.yaml`: compose project riêng, không dùng env_file hay CA Supabase, chỉ một service DB và volume riêng. Không đổi `compose.yaml` cũ.
- `server/scripts/sepay-local-guard.cjs`: chặn URL trừ PostgreSQL đúng literal IP 127.0.0.1, port 55432, user/database đã định; cấm query/hash để tránh override host, không dùng DNS localhost. Chặn môi trường production và URL DB ambient khác đích. Trước kết nối xác minh Docker image/name/label/running/binding/volume, một network riêng đúng label và password container khớp config; không in password.
- `server/scripts/sepay-local.cjs`: init/verify/baseline/migrate/seed/check. Không nạp dotenv. Sau guard kiểm tra current_database/current_user/inet_server_port. Migration runner độc lập, synchronize=false; seed cũ chạy subprocess với env tối thiểu, cwd riêng không có `.env` và chặn nếu cwd bị thêm `.env`.
- `server/src/migrations/SepayLocalFoundation1793289600000.ts`: chỉ CREATE ba bảng/index SePay; không ALTER/UPDATE/DELETE dữ liệu cũ. Đăng ký **chỉ trong runner local**, chưa đăng ký vào script migrate chung để tránh vô tình áp dụng Supabase. down từ chối tự xóa dữ liệu.
- `server/test/sepay-local-guard.test.cjs`: guard URL/container và thử runner bằng URL remote giả, không kết nối mạng.

Ba bảng: `sepay_payment_details`, `sepay_transactions`, `sepay_transaction_reviews`. Mã transfer_content có CHECK tiền tố `tkh` thường + 3–10 chữ/số; không default độ dài 10. Unique event theo environment/integration_account/ID webhook và riêng ID API; FK payment nullable cho event chưa ghép được. Hai ID không tự ánh xạ. Có lease token/deadline, retry và review fields phục vụ P2/P3. Chưa có worker/ownership runtime cho các bảng: thuộc P2/P3. Append-only review hiện là yêu cầu ứng dụng, chưa khẳng định có trigger DB chặn sửa.

## Sự cố và cách xử lý

Lần init đầu container healthy nhưng Docker network internal không công bố port host; guard phát hiện không khớp binding và chặn trước kết nối PostgreSQL. Chuyển sang bridge network riêng có label, giữ bind 127.0.0.1. Chỉ down compose project mới (không `-v`, không xóa volume) rồi khởi động lại; không đụng compose project pbl6. Mạng riêng hiện **không phải internal/air-gap**; bảo vệ đích kết nối dựa trên URL allowlist, Docker attestation và credential riêng.

Guard áp dụng cho **runner SePay local mới**, không bảo vệ khi ai đó tự gọi script migrate/seed cũ. Vì yêu cầu không tác động luồng cũ, các script cũ giữ nguyên. Trong quá trình SePay chỉ dùng runner này; P2/P3 phải có launcher API/worker áp dụng cùng guard trước khi start. Không chạy API/worker bằng `.env` hiện có. Người có quyền sửa config/Docker/scripts vẫn có thể vượt guard; đây là chống nhầm môi trường, không phải sandbox chống quản trị viên máy.

## Runbook

Từ thư mục `server`, sau khi chắc chắn shell không chứa URL DB remote (runner sẽ từ chối nếu có):

```powershell
npm run build
node scripts/sepay-local.cjs init
node scripts/sepay-local.cjs verify
node scripts/sepay-local.cjs migrate
node scripts/sepay-local.cjs check
```

Seed đã chạy; không cần chạy lại mỗi lần. Lần dựng mới dùng baseline → seed → migrate để kiểm chứng upgrade có dữ liệu giả. Không copy password vào tài liệu. Không chạy docker compose down -v, drop/reset database để thử lại. Cổng 8000/ngrok hiện không trỏ môi trường SePay local mới; chỉ DB được tạo ở P1. Kết nối API/ngrok thuộc giai đoạn sau.
